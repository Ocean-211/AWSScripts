4. List potential trust matches
This is the most relevant query for identifying possible --probe-role-arn candidates:

jq -r '
  .profiles[]
  | .profile as $profile
  | .source_identity.account as $account
  | .source_identity.arn as $source
  | .instance_profiles[]?
  | .instance_profile_name as $instance_profile
  | .roles[]?
  | select(
      .source_profile_is_potential_trust_match == true
    )
  | [
      $profile,
      $account,
      $source,
      $instance_profile,
      .role_name,
      .role_arn
    ]
  | @tsv
' "$REPORT" |
column -t -s $'\t'

output provides the follwoing:

AWS CLI profile
AWS account ID for --allowed-account
Source identity ARN
Instance-profile name
Role name
Role ARN for --probe-role-arn

9. Identify attached and orphaned instance profiles

Profiles attached to EC2

jq -r '
  .profiles[]
  | .profile as $profile
  | .instance_profiles[]?
  | select(
      ((.ec2_associations // []) | length) > 0
    )
  | [
      $profile,
      .instance_profile_name,
      .instance_profile_arn,
      (
        .ec2_associations
        | map(.region + ":" + .instance_id)
        | join(",")
      )
    ]
  | @tsv
' "$REPORT" |
column -t -s $'\t'

Profiles with no discovered EC2 association

jq -r '
  .profiles[]
  | .profile as $profile
  | .instance_profiles[]?
  | select(
      ((.ec2_associations // []) | length) == 0
    )
  | [
      $profile,
      .instance_profile_name,
      .instance_profile_arn,
      ((.roles // []) | map(.role_name) | join(","))

8. Correlate trust exposure with role impact

The most important roles are those with both:

A potentially broad assumption path
High-impact permissions

jq '
  .profiles[]
  | .profile as $profile
  | .source_identity.account as $account
  | .instance_profiles[]?
  | .instance_profile_name as $instanceProfile
  | .roles[]?
  | . as $role
  | [
      .findings[]?
      | select(
          .category == "TrustPolicy"
          or .category == "OIDCTrust"
          or .category == "FederatedTrust"
          or .category == "SAMLTrust"
          or .category == "ServiceTrust"
          or .category == "TrustCondition"
        )
      | select(
          .severity == "HIGH"
          or .severity == "CRITICAL"
        )
    ] as $trustFindings
  | [
      .findings[]?
      | select(
          .category == "PrivilegeEscalationPermission"
          or .category == "HighImpactPermission"
        )
      | select(
          .severity == "HIGH"
          or .severity == "CRITICAL"
        )
    ] as $impactFindings
  | select(
      ($trustFindings | length) > 0
      and ($impactFindings | length) > 0
    )
  | {
      aws_profile: $profile,
      account: $account,
      instance_profile: $instanceProfile,
      role_name: $role.role_name,
      role_arn: $role.role_arn,
      ec2_associations: $role.ec2_associations,
      trust_findings: $trustFindings,
      permission_findings: $impactFindings
    }
' "$REPORT" > "$EVIDENCE_DIR/high_priority_roles.json"

  | .profile as $profile

5. Identify cross-account trusts
jq '
  .profiles[]
  | .profile as $profile
  | .source_identity.account as $targetAccount
  | .instance_profiles[]?
  | .instance_profile_name as $instanceProfile
  | .roles[]?
  | .role_arn as $role
  | .trust_policy.Statement[]?
  | select(
      .Effect == "Allow"
      and .Principal.AWS != null
    )
  | (.Principal.AWS | if type == "array" then .[] else . end) as $principal
  | select(
      ($principal | type) == "string"
      and ($principal | test("^arn:aws:iam::[0-9]{12}:"))
    )
  | ($principal | capture("^arn:aws:iam::(?<account>[0-9]{12}):").account) as $trustedAccount
  | select($trustedAccount != $targetAccount)
  | {
      aws_profile: $profile,
      target_account: $targetAccount,
      instance_profile: $instanceProfile,
      role_arn: $role,
      trusted_principal: $principal,
      trusted_account: $trustedAccount,
      condition: (.Condition // {}),
      external_id_present: (
        ((.Condition // {}) | tostring)
        | contains("sts:ExternalId")
      )
    }
' "$REPORT"

***************************************************************
Prioritize:

External account trust with no ExternalId
External account root trust
External IAM user trust
External IAM role trust using broad conditions
Trust to an account that is no longer an approved vendor or integration

Remember that missing ExternalId is particularly relevant for third-party delegated access, but not every legitimate cross-account trust requires it.
